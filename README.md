# Telegram Memory Bot

Telegram-бот с краткосрочной и долгосрочной памятью на Python.
Проект демонстрирует работу Telegram-бота с краткосрочной и долгосрочной памятью на базе ChromaDB, интеграцией LLM и поиском по документам.

Бот умеет:

* вести диалог с использованием краткосрочной памяти;
* сохранять сообщения в долгосрочную память;
* восстанавливать долгосрочную память после перезапуска приложения;
* искать информацию в загруженных документах;
* использовать найденную информацию при формировании ответа;
* полностью очищать личную память пользователя командой `/reset`.

---

## 1. Цель проекта

Основная задача проекта — на практике показать разницу между ботом без долгосрочной памяти и ботом, который сохраняет контекст между запусками приложения.

В проекте реализованы два уровня памяти:

* **краткосрочная память** — история текущего диалога;
* **долгосрочная память** — данные пользователя, сохранённые в ChromaDB.

Также отдельно хранится база знаний из загруженных документов.

## 3. Архитектура памяти

В проекте используются две независимые коллекции ChromaDB.

### `user_memory`

Долгосрочная память пользователя.

В неё сохраняются:

* сообщения пользователя;
* ответы ассистента;
* embeddings этих сообщений.

При следующем запросе бот выполняет поиск по этой коллекции и передаёт релевантные записи в системный промпт LLM.

### `documents`

Отдельная база знаний.

В неё попадают фрагменты загруженных файлов:

* TXT;
* PDF;
* DOCX.

Для каждого фрагмента создаётся embedding, после чего он сохраняется в ChromaDB.

Таким образом, личная память пользователя и база знаний документов не смешиваются.

---

## 4. Как работает запрос

Общий сценарий обработки сообщения:

```text
Пользователь
     ↓
Telegram Bot
     ↓
Краткосрочная память
     ↓
Создание embedding запроса
     ↓
Поиск в user_memory
     ↓
Поиск в documents
     ↓
Формирование system prompt
     ↓
LLM через ProxyAPI
     ↓
Ответ пользователю
     ↓
Сохранение сообщения и ответа
     ↓
ChromaDB
```

При этом краткосрочная память используется для контекста текущего диалога, а долгосрочная память позволяет сохранять информацию между перезапусками приложения.

---

## 5. Краткосрочная память

Краткосрочная память реализована в `app/memory.py`.

Для каждого пользователя хранится ограниченная история последних сообщений.

Она существует в памяти работающего Python-процесса и используется для понимания текущего диалога.

После полного завершения приложения эта часть памяти очищается.

---

## 6. Долгосрочная память

Долгосрочная память реализована с помощью ChromaDB.

Она находится в:

```text
data/chroma/
```

Коллекция:

```text
user_memory
```

В отличие от краткосрочной памяти, данные ChromaDB сохраняются на диске.

Поэтому после остановки и повторного запуска бота ранее сохранённая информация может быть найдена и использована снова.

---

## 7. Очистка памяти

Для полного удаления личной памяти пользователя реализована команда:

```text
/reset
```

После выполнения команды бот отвечает:

```text
Память очищена. Начинаем диалог с чистого листа.
```

Команда очищает:

* краткосрочную историю;
* долгосрочную память конкретного пользователя.

При этом коллекция `documents` не удаляется, поэтому загруженные документы продолжают использоваться как отдельная база знаний.

---

## 8. Загрузка документов

Бот поддерживает документы следующих форматов:

```text
TXT
PDF
DOCX
```

После загрузки:

1. файл сохраняется в `data/uploads/`;
2. из него извлекается текст;
3. текст разбивается на небольшие фрагменты;
4. для каждого фрагмента создаётся embedding;
5. фрагменты сохраняются в коллекцию `documents`.

После этого пользователь может задать вопрос по содержимому документа.

Например:

```text
Что говорится в загруженном документе об оплате?
```

Бот выполняет семантический поиск и использует найденный фрагмент при формировании ответа.

---

## 9. Сравнение версии без долгосрочной памяти и версии с памятью

### Версия без долгосрочной памяти

В исходной версии проекта использовалась краткосрочная память текущего диалога.

После завершения приложения история диалога исчезает.

То есть:

```text
Диалог
  ↓
Память процесса
  ↓
Перезапуск приложения
  ↓
История потеряна
```

### Версия с долгосрочной памятью

В текущей версии добавлена постоянная память на основе ChromaDB.

```text
Диалог
  ↓
Краткосрочная память
  ↓
Сохранение в ChromaDB
  ↓
Перезапуск приложения
  ↓
Поиск ранее сохранённой информации
  ↓
Контекст снова доступен LLM
```

Главное отличие заключается в том, что долгосрочная память не зависит от времени жизни Python-процесса.

## 10. Проведённое тестирование

### Тест 1. Запоминание информации

Пользователь сообщил:

```text
Меня зовут Дмитрий. Я изучаю Python и занимаюсь разработкой Telegram-ботов.
```

После этого был задан вопрос:

```text
Что ты знаешь обо мне?
```

Бот корректно использовал информацию из текущего диалога.

---

### Тест 2. Сохранение после перезапуска

Бот был остановлен через:

```text
Ctrl+C
```

и запущен повторно.

Долгосрочная память сохраняется в ChromaDB и не зависит от текущего процесса приложения.

---

### Тест 3. Очистка памяти

Была выполнена команда:

```text
/reset
```

После чего бот сообщил:

```text
Память очищена. Начинаем диалог с чистого листа.
```

Проверка базы показала:

```text
documents: 1
user_memory: 0
```

Это означает, что личная память пользователя была очищена, а база документов осталась.

---

### Тест 4. Повторное накопление памяти

После очистки снова были отправлены сообщения:

```text
Меня зовут Дмитрий. Я изучаю Python и занимаюсь разработкой Telegram-ботов.
```

и:

```text
Что ты знаешь обо мне?
```

После этого количество записей в долгосрочной памяти снова увеличилось:

```text
user_memory: 6
```

Таким образом, после очистки память снова может накапливаться.

---

### Тест 5. Работа с документами

Был загружен тестовый TXT-файл со следующим содержимым:

```text
Это тестовый документ для проверки долгосрочной памяти.

Компания работает с обращениями клиентов.

Оплата банковской картой обрабатывается в течение нескольких минут.
```

После загрузки бот смог извлечь содержимое документа.

На вопрос:

```text
Что говорится в загруженном документе об оплате?
```

бот нашёл соответствующий фрагмент и ответил:

```text
В документе указано: «Оплата банковской картой обрабатывается в течение нескольких минут.»
```

Это подтвердило работоспособность семантического поиска по загруженным документам.

## 11. Проверка содержимого ChromaDB

Состояние коллекций можно проверить командой:

```bash
python -c "import app.memory; print('documents:', app.memory.documents_collection.count()); print('user_memory:', app.memory.user_memory_collection.count())"
```

Пример результата:

```text
documents: 1
user_memory: 10
```

Здесь:

* `documents` — количество сохранённых фрагментов документов;
* `user_memory` — количество записей долгосрочной памяти пользователя.

## 15. Основные файлы

### `app/bot.py`

Основная логика Telegram-бота:

* обработка `/start`;
* обработка `/reset`;
* загрузка документов;
* обработка текстовых сообщений;
* поиск по памяти;
* обращение к LLM;
* сохранение сообщений.

### `app/memory.py`

Работа с памятью:

* краткосрочная история;
* коллекция `user_memory`;
* коллекция `documents`;
* сохранение и поиск записей;
* очистка памяти пользователя.

### `app/documents.py`

Работа с документами:

* TXT;
* PDF;
* DOCX;
* извлечение текста;
* разбиение на фрагменты;
* создание embeddings;
* сохранение в ChromaDB.

### `app/llm.py`

Работа с LLM и embeddings через ProxyAPI.

### `app/config.py`

Загрузка конфигурации и переменных окружения.

## 16. Ограничения текущей реализации

Текущая версия является учебным MVP.

Долгосрочная память сохраняет сообщения пользователя и ответы ассистента как векторные записи. Отдельного этапа автоматического выделения только фактов о пользователе пока нет.

В более сложной версии можно добавить:

* отдельное извлечение фактов;
* структурированную память пользователя;
* удаление отдельных воспоминаний;
* срок жизни воспоминаний;
* PostgreSQL или другую внешнюю БД для production-развёртывания;
* более сложную стратегию отбора релевантных воспоминаний.

---

## 17. Результат

В рамках задания реализован Telegram-бот с двумя уровнями памяти.

Краткосрочная память обеспечивает контекст текущего диалога, а долгосрочная память на базе ChromaDB позволяет сохранять информацию между перезапусками приложения.

Также реализована команда `/reset`, позволяющая полностью очистить личную память пользователя, при этом не удаляя отдельную базу знаний загруженных документов.

Проект протестирован на сценариях накопления памяти, перезапуска приложения, очистки памяти и поиска информации в загруженном документе.
